# RecomAI

A React product discovery app that turns natural-language requests into up to three AI-generated product suggestions. The included 22-item catalog remains available to browse and is optional context for the AI; recommendations are generated as complete product cards and are not restricted to those demo items.

AI-generated prices and specifications are estimates. Each suggestion includes a shopping search link so users can check current listings before buying.

## Stack

- Vite, React and TypeScript
- Tailwind CSS
- Vercel serverless function for the recommendation request
- OpenAI-compatible SDK on the server side only

## Features

- Responsive catalog of 22 fictional products across smartphones, laptops, headphones, smartwatches, tablets and accessories
- Natural language preference input with example prompt chips
- API key modal with provider-specific links, editable model IDs, a masked key field, and an optional remember for this tab control
- Search, category filter and sorting
- Product detail view
- Up to three dynamic product suggestions with a match score, explanation, estimated price and shopping search link
- Loading, empty and error states throughout
- Accessible dialogs, labels, focus states and reduced motion support

## Getting started

```
npm install
npm run dev
```

Open the local URL that Vite prints.

The recommendation request calls the serverless route at `api/recommend.ts`. In local development the same endpoint logic lives in `api/recommend-core.ts` and is served by a Vite middleware plugin, so `npm run dev` and `npm run preview` both run the full recommendation flow against the selected provider with your supplied key. In production on Vercel the `api/recommend.ts` function runs the identical core. No extra tooling is required for local testing.

## How the API key is handled

- The key lives in React memory by default
- If the visitor selects remember for this tab, the key is written to sessionStorage only, and it clears when the tab closes
- localStorage is never used for the key
- The key is sent in the `x-api-key` header, with the selected provider in `x-provider` to the serverless route
- The key never appears in a URL, in a server response, in logs or in the committed source

## Recommendation endpoint

`POST /api/recommend`

Request body:

```
{
  "preference": "I want a phone under $500",
  "products": [],
  "model": "openai/gpt-oss-120b"
}
```

The selected provider key is passed in the `x-api-key` header, and the provider ID is passed in `x-provider`.

The server validates the body and key, creates an OpenAI-compatible client for that provider and request only, asks the model for structured JSON, then validates and normalizes each product generated by the model. Duplicate products are removed, text fields and feature lists are bounded, prices are treated as estimates, and scores are clamped to 0–100. The server generates a Google Shopping search link from each product name instead of trusting URLs supplied by a model.

Response shape:

```
{
  "summary": "These products best match your budget and priorities.",
  "recommendations": [
    { "productId": "brand-phone-model", "product": { "id": "brand-phone-model", "name": "Phone Model", "brand": "Brand", "category": "smartphones", "price": 450, "rating": 0, "reviewCount": 0, "image": "indigo", "description": "A suitable phone", "features": ["Long battery life"], "tags": ["battery"], "featured": false, "priceIsEstimate": true, "sourceUrl": "https://www.google.com/search?tbm=shop&q=Brand%20Phone%20Model" }, "score": 96, "reason": "Estimated to fit the budget and battery-life priority." }
  ]
}
```

## Deploying to Vercel

1. Push this project to a Git host or run the Vercel CLI from the project root
2. `vercel link` to connect a project
3. `vercel build` and `vercel deploy` to create a preview deployment
4. Promote to production from the Vercel dashboard after review

No server environment secret is required for visitor keys because each selected provider key is supplied per request. The model selected in the key dialog is sent with each request and takes precedence over server defaults.

## AI providers

RecomAI works with several providers. Pick one in the API key modal and paste that provider's key. Groq, Gemini and OpenRouter offer limited free usage or free models; quotas and model availability can change. The selected model ID is editable in the key dialog, so it can match the models enabled for your provider account.

| Provider | Default model | Free tier | Get a key |
| --- | --- | --- | --- |
| OpenAI | gpt-4o-mini | no | https://platform.openai.com/api-keys |
| Groq | openai/gpt-oss-120b | yes, with limits | https://console.groq.com/keys |
| Google Gemini | gemini-3.5-flash-lite | yes | https://aistudio.google.com/apikey |
| OpenRouter | x-ai/grok-4.1-fast:free | yes | https://openrouter.ai/keys |
| Anthropic Claude | claude-haiku-5-5 | no | https://console.anthropic.com/settings/keys |
| xAI Grok | grok-4.7 | no | https://console.x.ai |
| Mistral | mistral-small-latest | no | https://console.mistral.ai/api-keys |

The key you enter is sent only in the request header and is never stored on the server. It stays in memory, or in sessionStorage when you choose remember for this tab. The provider choice and model ID are stored in localStorage as preferences, and saved search results, including the provider/model used, are cached in localStorage. The key itself is never written to localStorage.

## Environment variables

No environment variable is required to run or deploy RecomAI, because the AI key is supplied by the visitor per request. Optional `RECOMAI_*_MODEL` variables provide fallback models for direct API callers that omit `model`. The web UI always sends its selected model, so these server defaults cannot silently replace the model shown in the dialog:

```
RECOMAI_OPENAI_MODEL=gpt-4o-mini
RECOMAI_GROQ_MODEL=openai/gpt-oss-120b
RECOMAI_GOOGLE_MODEL=gemini-3.5-flash-lite
RECOMAI_OPENROUTER_MODEL=x-ai/grok-4.1-fast:free
RECOMAI_ANTHROPIC_MODEL=claude-haiku-5-5
RECOMAI_XAI_MODEL=grok-4.7
RECOMAI_MISTRAL_MODEL=mistral-small-latest
```

## Free deployment on Vercel

The Vercel Hobby plan runs both the static site and the serverless route.

Using the Vercel CLI:

```
npm install -g vercel
vercel login
vercel
```

Accept the detected settings (framework Vite, build command npm run build, output dist). The first run creates a preview URL. To publish to the production URL:

```
vercel --prod
```

No environment variable needs to be set for a working deployment. Set a `RECOMAI_*_MODEL` value only to choose a fallback for requests that do not specify a model.
